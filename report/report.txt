\begin{abstract}
Criminal risk prediction in social networks presents a challenging machine learning problem due to severe class imbalance, small dataset sizes, and the relational nature of criminal behaviour. This paper investigates whether graph-structural features improve node classification performance over behavioural node attributes alone, using the POLE-50 dataset modelled as a property graph in Neo4j. We design four progressive feature engineering strategies and evaluate them using Logistic Regression pipelines within the Neo4j Graph Data Science library\cite{neo4j-gds}. We further compare FastRP graph embeddings at three dimensionalities against Node2Vec\cite{node2vec} embeddings and a conventional Random Forest baseline. 
\end{abstract}

\section{Introduction}

Criminal network analysis has traditionally depended on manual investigations and standard database searches to identify suspects and persons of interest. With the rise of graph databases and graph machine learning, investigators can now go beyond individual information and also use a person’s connections and position within a network to predict criminal risk.

The POLE (Person, Object, Location, Event) data model \cite{pole} is widely used by UK law enforcement for criminal intelligence. It represents individuals, crimes, locations, vehicles, and communication records as a property graph, where relationships between entities encode investigative relevance. This structure makes it a good candidate for graph-based machine learning, where both node properties and network topology can be exploited simultaneously.

This paper addresses the research question:\\
\textbf{\textit{Can we predict criminal risk for individuals in a social crime network, and does incorporating graph-structural features improve classification performance over node attributes alone?}}
\\ We frame this as a node classification task on the POLE-50 dataset, where the target label \texttt{isInvolved} indicates whether a Person node has at least one \texttt{PARTY\_TO} relationship to a Crime node.

In this paper, we will discuss the following:
\begin{enumerate}
    \item We built four pipelines to compare different feature engineering strategies ranging from node attributes to graph embeddings; 
    \item we demonstrated that scalar graph metrics actively degrade performance when combined with discriminative features on a small imbalanced dataset
    \item we showed that FastRP embeddings at 64 dimensions outperform all feature sets\cite{fastrp}
\end{enumerate}

\section{Methodology}

\subsection{Dataset and Graph Model}

The POLE-50 dataset is a synthetic but realistic criminal intelligence dataset distributed by Neo4j as an example graph for forensic analysis. It was loaded into a Neo4j database instance by restoring a provided dump file, which preserved the complete graph structure, including all nodes, relationships, properties, and indexes. In total, the graph contains 61,521 nodes and 105,840 relationships across multiple entity types and interactions.

The graph contains 11 node types: Person, Crime, Location, PostCode, Area, Officer, Phone, PhoneCall, Email, Vehicle, and Object. For the purposes of this study, all analysis is scoped to Person nodes as the classification targets. The dataset contains 369 Person nodes and 29 criminally involved individuals, representing a severe class imbalance.

Relationships relevant to this study include \texttt{KNOWS} (social acquaintance), \texttt{FAMILY\_REL} (family connection), \texttt{KNOWS\_SN} (social network connection), \texttt{PARTY\_TO} (person directly involved in a crime), \texttt{HAS\_PHONE} (person linked to a phone number), \texttt{CALLER} and \texttt{CALLED} (phone call direction), and \texttt{INVOLVED\_IN} (vehicle linked to a crime). Figure~\ref{fig:schema} shows the graph schema of the dataset.

\subsection{Data Preprocessing}

Prior to feature engineering, several data quality checks were performed. The graph was inspected for isolated nodes, yielding 22 isolated Vehicle nodes and 1 isolated Person node. The isolated vehicles had no impact on analysis as all pipelines were scoped to Person nodes. The isolated Person node had zero values across all features, and so this node was removed from the graph before pipeline training as it represented a data quality outlier.

No duplicate relationships were found. All Person nodes were verified to hold valid NHS number identifiers. Feature completeness was verified after each property-writing step using verification queries that confirmed no null values remained before pipeline execution.

A critical data leakage issue was identified and resolved during feature engineering. The feature \texttt{crimeCount}, representing the number of crimes a person is linked to, was initially considered as an input feature. However, since \texttt{crimeCount} is derived directly from \texttt{PARTY\_TO} relationships, the same source as the \texttt{isInvolved} label, including it as a feature would allow the model to trivially read the answer. This feature was excluded from all pipeline configurations. Similarly, \texttt{uniqueCrimeTypes}, which counts distinct crime categories per person, was excluded for the same reason.

A feature separability analysis was conducted before finalising feature sets. For each candidate feature, average values were computed separately for the criminal and non-criminal classes. Features showing a class separation ratio below 1.5x were deemed to have insufficient discriminative power for a dataset with only 29 positive examples. This analysis revealed that degree-based features (knowsDegree, familyDegree, socialDegree), centrality measures (betweenness \cite{betweenness}, degree centrality, PageRank, closeness), triangle count, and neighbourhood aggregations all showed separation ratios between 1.03x and 1.43x. Only two features demonstrated meaningful separation: \texttt{criminalVehicleCount} (0.0 vs 0.79, effectively infinite ratio) and \texttt{nightCallRatio} (0.167 vs 0.316, 1.89x ratio).

Betweenness centrality was found to have a heavily right-skewed distribution with mean 625, standard deviation 879, and maximum 5275. A log transformation was applied before inclusion in any pipeline: $\texttt{betweennessLog} = \log(\texttt{betweenness} + 1)$.

\subsection{Graph Construction and Projections}

Three named in-memory graph projections were created. The \texttt{social} projection contains Person nodes connected by undirected KNOWS relationships and was used for betweenness centrality and Louvain \cite{louvain} community detection. The \texttt{crime-associates} projection uses the same topology and was used for triangle counting. The \texttt{social-full} projection includes Person nodes connected by undirected KNOWS, FAMILY\_REL, and KNOWS\_SN relationships, and includes all node properties as named features for ML pipeline training.

The \texttt{social-full} projection was constructed in two phases. In the first phase it was projected without the embedding property, which did not yet exist. FastRP embeddings were then generated and written to nodes. In the second phase the projection was dropped and recreated with the embedding property included, making it a pipeline feature.

The target label \texttt{isInvolved} was derived by traversing the graph: each Person node was assigned 1 if it had at least one outgoing \texttt{PARTY\_TO} relationship to a Crime node, and 0 otherwise. This derivation from graph structure rather than an external attribute file is itself a demonstration of graph-native data preparation.

The \texttt{nightCallRatio} feature was computed as the proportion of outgoing phone calls made between midnight and 5am, motivated by our Milestone 1 queries showing that late-night call activity correlates with criminal coordination in this dataset. The \texttt{criminalVehicleCount} feature counts vehicles linked to crimes that the person was also party to, capturing direct crime-scene vehicle involvement.

FastRP embeddings were generated using the \texttt{social-full} projection with embedding dimension 64 and random seed 42. Embeddings were generated transductively on the full graph prior to the train-test split, which is standard practice for fixed closed graphs but would not generalise to an inductive setting with unseen nodes.

\subsection{Node Classification Pipelines}

All classification experiments were conducted using the Neo4j GDS node classification pipeline API. Each pipeline follows a five-step configuration: creation, classifier addition, feature selection, train-test split configuration, and training with evaluation.

All pipelines used a test fraction of 0.2 and 5-fold cross-validation on the training set. The random seed was fixed at 42 for reproducibility. Four penalty values (0.001, 0.01, 0.1, 1.0) were added to each Logistic Regression pipeline and GDS automatically selected the best via cross-validation.

Four primary pipelines were designed with progressively richer feature sets:

\textbf{Pipeline A -- Behavioural Features:} nightCallRatio, criminalVehicleCount. This represents the strongest scalar baseline identified through feature separability analysis.

\textbf{Pipeline B -- Behavioural + Structural:} All of Pipeline A plus betweennessLog, triangleCount. Tests whether GDS-computed graph structural metrics improve over the behavioural baseline.

\textbf{Pipeline C -- Behavioural + Structural + Neighbourhood:} All of Pipeline B plus criminalNeighborCount, criminalFamilyCount. Tests whether indirect criminal exposure adds further predictive value.

\textbf{Pipeline D -- Graph Embeddings:} FastRP embedding vector only. Tests whether holistic graph representation outperforms all hand-crafted feature sets.

To evaluate embedding algorithm sensitivity, Node2Vec embeddings were also generated and evaluated as Pipeline E. To evaluate embedding dimensionality sensitivity, FastRP was tested at 32, 64, and 128 dimensions.

\subsection{Evaluation Metrics}

Three metrics were reported for all experiments. Accuracy is included for completeness but is misleading given the 92.4 percent majority class -- a classifier predicting non-criminal for all nodes achieves 92.4 percent accuracy without learning anything. F1-Weighted accounts for class frequency but remains biased toward the majority class. F1-Macro computes F1 separately for each class and averages equally, treating both classes as equally important regardless of size. F1-Macro is the primary evaluation metric throughout this study.

\subsection{Embedding Dimensionality}

FastRP performance varied substantially across embedding dimensions. At 32 dimensions the model collapsed to majority class prediction (F1-Macro 0.4861), identical to the uninformative baseline. At 64 dimensions the model achieved peak performance of 0.7751 F1-Macro. At 128 dimensions performance degraded to 0.70, suggesting mild overfitting. This demonstrates that 64 dimensions represents the optimal balance between representational capacity and the available training signal for a graph of 369 nodes.

\section{Discussion}

\subsection{Scalar Features Actively Degrade Performance}

We found that Pipelines B and C perform worse than Pipeline A. Adding structural features (betweenness, triangle count) and neighbourhood features (criminal neighbour count, criminal family count) to the two effective behavioural features does not only fail to help, it returns performance to the uninformative baseline of 0.4861 F1-Macro. This suggests that on a severely imbalanced dataset with only 29 positive training examples, additional scalar features introduce noise dimensions that overwhelm the discriminative signal from \texttt{nightCallRatio} and \texttt{criminalVehicleCount}. A linear classifier with insufficient positive examples cannot reliably identify which dimensions are informative when given many weakly separating features alongside strongly separating ones.

This finding has practical implications: feature selection based on empirical class separability analysis, as conducted in this study, is essential for small imbalanced graph datasets. Naively adding more graph features degrades rather than improves performance.

\subsection{Embeddings Capture What Scalars Cannot}

Pipeline D-64 achieves F1-Macro of 0.7751, a 12.4 percent relative improvement over the scalar ceiling of 0.6895. The FastRP embedding encodes multi-hop neighbourhood structure (who a person knows, who those people know, and so on across multiple hops) into a dense 64-dimensional vector. This avoids the noise accumulation problem of individual scalar features because the embedding algorithm implicitly weights structural dimensions by their variance across the graph. The linear classifier then operates in an embedding space where criminal and non-criminal nodes are geometrically separable, as evidenced by Logistic Regression outperforming Random Forest on the same embeddings.

\subsection{Node2Vec Fails on Small Sparse Graphs}

Node2Vec embeddings collapsed to majority class prediction regardless of parameter configuration. This is likely due to the graph’s small size and sparse connectivity. Node2Vec learns embeddings by training on random walks through the graph, which requires sufficient structural diversity to produce meaningful representations. In a graph with only 369 nodes and limited connectivity, the random walks may repeatedly traverse similar neighbourhoods, reducing the quality of the learned embeddings. FastRP’s matrix-based approach appears more robust under these conditions. This suggests that for criminal intelligence graphs of this scale, random projection methods may be more suitable than random-walk-based neural embedding methods.

\subsection{Communty Detection as a Feature}

The Louvain algorithm identified community 91 as containing 8 of 29 criminals (27.6 percent of all criminal nodes), confirming that community membership correlates with criminal involvement. However, communityId as a raw integer feature was not usable in Logistic Regression because averaging community IDs is mathematically meaningless; community 91 and community 233 are categorical labels, not ordinal values. In future work, community membership could be one-hot encoded or used to generate community-level aggregate features.

\subsection{Class Imbalance as the Fundamental Constraint}

All results must be interpreted in the context of severe class imbalance: 340 non-criminals versus 29 criminals (7.6 percent positive rate). With an 80/20 train-test split, the test set contains approximately 6 criminal nodes. This means F1-Macro scores have high variance as a single misclassification at the boundary can shift results substantially. The plateau at F1-Macro 0.4861 across multiple pipeline configurations represents the majority class classifier baseline: a model that predicts non-criminal for every node achieves this score without learning anything about criminal structure.

\section{Future Work}

Several directions would strengthen this analysis. First, applying this methodology to a larger criminal network dataset with hundreds of thousands of nodes would allow Node2Vec and higher-dimensional embeddings to be properly evaluated and would reduce the variance introduced by having only 29 positive examples. Second, implementing an inductive embedding approach i.e. generating embeddings for test nodes independently of training nodes, would address the transductive leakage limitation noted in the methodology. Third, community membership could be incorporated as a properly encoded categorical feature rather than a raw integer, potentially recovering discriminative signal from the Louvain output. Fourth, graph neural network approaches such as GraphSAGE or Graph Attention Networks could be evaluated as alternatives to the GDS pipeline framework, potentially capturing richer structural patterns than FastRP. Fifth, SMOTE \cite{imbalance} or other oversampling techniques applied outside GDS could address the class imbalance more directly than the current approach.

\section{Conclusion}

This paper investigated criminal risk prediction as a node classification task on the POLE-50 dataset using the Neo4j Graph Data Science library. We evaluated four progressive feature engineering strategies and multiple embedding configurations, yielding four principal findings.

First, a systematic feature separability analysis identified only two scalar features with meaningful discriminative power: \texttt{criminalVehicleCount} and \texttt{nightCallRatio}, with class separation ratios of effectively infinite and 1.89x respectively. All other features including degree counts, centrality measures, and neighbourhood aggregations showed insufficient separation.

Second, adding structural and neighbourhood graph features to the effective behavioural baseline actively degraded performance, returning F1-Macro from 0.6895 to 0.4861. This demonstrates that feature quantity is counterproductive on small imbalanced datasets. Noise accumulation from weakly discriminative features overwhelms the signal from strongly discriminative ones.

Third, FastRP embeddings at 64 dimensions achieved the best overall performance of 0.7751 F1-Macro, a 12.4 percent relative improvement over the scalar ceiling. Embedding dimensionality proved critical: 32 dimensions collapsed to baseline, 64 was optimal, and 128 showed mild overfitting.

Fourth, Node2Vec embeddings failed entirely on this dataset, collapsing to majority class prediction regardless of parameter configuration. This is attributed to insufficient graph density and size for the random walk neural training process to converge meaningfully.

Together these findings demonstrate that for small sparse criminal network graphs, graph embeddings via random projection methods represent the most effective approach to node classification, and that individual scalar graph metrics should be selected empirically rather than assumed to be informative.
